# Wrist Review local app

This folder contains the source of the local-only, browser-based Wrist Review
research prototype. It calls only the verified, frozen Checkpoint 1 Model B
bundle and the deterministic safety policy. It is not a clinical deployment
and it does not implement the planned adaptive Agentic AI layer.

The accompanying product-flow PNG in
[`docs/app/concepts/wrist_review_concept_storyboard.png`](../../docs/app/concepts/wrist_review_concept_storyboard.png)
is conceptual artwork, **not an application screenshot**. The actual
interface is generated by the files in this folder when the local server runs;
an actual non-sensitive capture is in
[`docs/app/screenshots/`](../../docs/app/screenshots/).

## Run locally

Install the repository dependencies, place the authorized canonical Model B
bundle outside Git, then run the server from the repository root:

```powershell
$env:MURA_APP_MODEL_DIR = "C:\authorized-local-artifacts\MODEL_B_FINE_TUNING"
python apps/wrist_review/server.py
```

Open `http://127.0.0.1:8601` in a browser.

The default artifact location is
`local_artifacts/MODEL_B_FINE_TUNING/`, which is intentionally not committed.
The expected files and checksum are specified in
[`configs/model_b_artifact_bundle.json`](../../configs/model_b_artifact_bundle.json).

## Data and safety boundaries

- Image bytes stay in process memory for the local request only.
- The UI supports 1–8 views. A selection above eight is rejected and the
  reviewer must re-select; it is never silently truncated. Padding is never
  turned into a real view.
- The anatomy field is a **declared-anatomy routing input**, not an automatic
  body-part detector. Automatic body-part/support checking is planned and no
  clinical claim should be made from the current selector alone.
- QC and declared-anatomy checks execute before model inference.
- Unsupported/corrupt/missing inputs route safely without model inference.
- A model route may raise priority, never lower or replace human review.
- Use a non-identifying local alias. Do not put patient identifiers in the
  alias, selected folder name, or file names.
- Do not use official MURA `valid` labels for any app or agent selection.

## Deterministic routes

| Condition | Route | Model inference |
| --- | --- | --- |
| No views, duplicate files, or more than 8 views | Selection/API request rejected | No |
| Unsupported declared anatomy | `UNSUPPORTED` | No |
| Missing or unknown declared anatomy, or failed technical QC | `NEEDS_HUMAN_REVIEW` | No |
| Missing/invalid canonical bundle, policy, or checkpoint hash | Fail closed — no review result | No |
| Verified study mean reaches the frozen threshold, or views disagree across it | `RAISE_PRIORITY` | Yes |
| Verified study mean remains below threshold with no threshold disagreement | `STANDARD_HUMAN_REVIEW` | Yes |

If the canonical bundle, frozen policy, or checkpoint checksum is missing or
invalid, the app fails closed: it does not produce a model review result. The
Model screen shows the unavailable-bundle reason and the reviewer must correct
the local artifact setup before retrying.
